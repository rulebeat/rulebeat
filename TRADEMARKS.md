# Trademarks

"RuleBeat" and the RuleBeat logo are trademarks of Abdelrahman Hanafy. They are **not** covered by
the Apache-2.0 license that covers the platform's source code; see
[`LICENSE_SCOPE.md`](LICENSE_SCOPE.md). This is the normal split for an open-source project: the
code is free to use, modify, and redistribute; the name and mark that identify the *official*
project are not, so that a fork or a modified build can't present itself as RuleBeat itself.

## What's fine without asking

- Running RuleBeat, self-hosted, unmodified or modified, for your own use.
- Saying your deployment "runs RuleBeat" or "is built on RuleBeat" in factual, non-branding contexts
  (a blog post, an internal wiki page, a job posting).
- Linking to the project, quoting its docs, or writing about it (reviews, comparisons, tutorials).
- Contributing code back under Apache-2.0 (see [`CONTRIBUTING.md`](CONTRIBUTING.md)).

## What needs permission first

- Using the RuleBeat name or logo as the name/icon of a fork, a hosted service, or a commercial
  offering built on this code, in a way that could be mistaken for the official project.
- Any modified build that keeps the RuleBeat name/logo but has diverged from upstream in a way that
  could mislead users about what they're running.
- Using the logo in your own product's marketing, merchandise, or branding.

If in doubt, ask: [open an issue](https://github.com/rulebeat/rulebeat/issues) or reach out
directly. The goal is to keep the mark meaningful (so "RuleBeat" reliably refers to this project),
not to restrict legitimate use, self-hosting, or forking, all of which Apache-2.0 already protects.

## Reporting misuse

If you see the RuleBeat name or logo used in a way that misrepresents its origin or affiliation,
[open an issue](https://github.com/rulebeat/rulebeat/issues) or use the private contact in
[`SECURITY.md`](SECURITY.md).
